# A5: The search loop

Status: next. Planned at 2 hours. It needs no other task.

## The contract

From BETA.md: 8 running sums in plain Go. Done when amd64 and arm64 return
the same bits on random and awkward vectors.

## What BETA.md says about it

From "Vectors":

- The loop widens values to float64 and adds them in 8 running sums, value
  i going to sum i mod 8.
- It combines the sums in a fixed order at the end.
- Go doesn't reorder floating-point additions or flush denormals. It may
  fuse a multiply and an add, on ARM for example, but a float32 times a
  float32 is exact in float64, so fusing can't change the result.
- A vector's norm is kept beside it, and the distance is one minus the dot
  product divided by the two norms, kept between 0 and 2, as in 0.x. 0.x
  computes `1 - dot/(sqrt(na) * sqrt(nb))`, adding in plain order, and
  gives zero vectors a distance of 1 (`cosine` in `vectors.go`).

## Where it goes

Into its own small package, `beta/internal/vecmath`, Linux only with an
untagged `doc.go`, so the engine's packages from P4 on can import it.

## To settle, and write down in this file

- **The functions:** probably `Dot(a, b []float32) float64`, a norm built
  on the same loop, and the distance from a dot product and two norms. V1
  calls them, and may want the loop over a flat array of vectors instead
  of slices. Settle which.
- **The combining order:** for example `((s0+s1)+(s2+s3))+((s4+s5)+(s6+s7))`,
  with the tail of a vector whose length isn't a multiple of 8 going to the
  sums in turn too.
- **Same bits on both architectures:**
  - Record the bits on amd64 into a golden file in `testdata`, for random
    vectors and awkward ones. The awkward ones are subnormals, values near
    float32's largest, -0, lengths 1 to 17, 384, 1,536 and 65,536, and
    near-identical vectors.
  - Check against the file on arm64. CI has no Linux arm64 job yet, and
    `beta/` builds only on Linux, so the macOS job can't help. Add a job on
    `ubuntu-24.04-arm` for this package, which the release workflow already
    uses. P1 folds it into its own CI layout later.
- **Close to 0.x:** distances within `conformance.DistanceBound` of 0.x's,
  on the same random vectors.
- **Speed:** a benchmark per vector at 384 and 1,536 values, set against
  BETA.md's targets: 65 ms for 100,000 vectors of 384, and 26 ms for
  10,000 of 1,536. Earlier measurements are in the scratch notes for the
  targets. Record what it gives here.
