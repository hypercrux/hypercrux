# T1: Fault layer for data

Status: next, in one round with F2 and S2. Planned at 3 hours. It needs P3,
which is done.

## The contract

From BETA.md: the fault layer for data: unsynced writes lost or torn at a
simulated power cut, and any call made to fail at its nth use. Done when its
own tests show synced data surviving every cut.

## What's there already

- **The file calls** (P3): `fsys.File` and `fsys.FS`, which the fault layer
  wraps. BETA.md's "Testing" says the engine reaches the file only through
  them, so the crash tests can swap in a layer that loses unsynced writes,
  tears the last one, or makes any call fail.
- **The package map** (P3): the fault layers live in `beta/internal/fault`.
- **What leans on it:** T2 adds the names (create, rename, remove,
  directory sync, each kept or lost at a cut), T3 drives a cut at every
  write and a failure at every call, and F3, F5 and F8 pass their closing
  tests through it.

## To settle, and write down in this file

- **What a power cut does** to writes since the last sync: kept, lost, or
  torn, and at what granularity a write tears (whole sectors, say, in any
  order), so the model is no kinder than a real disk.
- **Failing a call at its nth use:** how a test picks the call and the
  error, and how it counts calls across files.
- **What sits underneath:** an in-memory disk, so the tests run without the
  real file system, which F2 writes in the same round. The names can stay
  simple and always durable here; losing them is T2's.
- **The tests:** synced data surviving every cut, unsynced data lost or torn
  as the model says, and every call failing at its nth use.
