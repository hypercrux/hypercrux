# Q1: Values and functions

Status: next, in one round with F8 and G3. Planned at 4 hours. It needs P3
and P5, which are done, and uses Q3's parser, which is done too.

## The contract

From BETA.md: values and functions: SQLite's comparison rules for untyped
values, arithmetic, the listed text and number functions, `LIKE`,
`BETWEEN`, `IN`, `IS NULL`. Done when A4's expression answers match
exactly.

## What's there already

- **The rules,** in `beta/SQL.md` under "Values": kinds, arguments and
  results, comparing, conversion before comparing, truth, arithmetic,
  numbers as text and text as numbers, CAST, concatenation, LIKE, IN,
  BETWEEN and IS, and what gets worked out. Under "Functions", the text and
  number functions and HyperCrux's own. SQL.md names SQLite's routine
  behind each rule.
- **The parser** (Q3), in `beta/internal/query`: the tree for expressions,
  with the sign rule applied, function names and argument counts checked,
  and the parameters counted. Q3.md's note under Q1 says how to read it.
- **The value type** (P3), in `beta/internal/value`, holding each kind bit
  for bit.
- **The corpus** (A4), in `beta/sqlcorpus/testdata/expressions.jsonl`:
  3,000 expressions as `SELECT <expression> AS v`, with arguments and 0.x's
  answers. Q3's `sqlite_test.go` checks trees against 0.x through `zerox`
  on random expressions as well.

## To settle, and write down in this file

- **Where the evaluator lives** in `beta/internal/query`, and how it takes
  an expression from the tree with its arguments and gives a value or an
  error of SQL.md's kind. Fields come from a row that Q4 and Q5 will hand
  it; for now an expression without fields is enough.
- **SQLite's hard parts,** which P5.md's note lists: the text of reals,
  CAST's affinity in comparisons, `min()` and `max()` on ties, and the signs
  in front of literals.
- **What's left out:** dates (Q2), aggregates and operators (Q4), and
  `walk()`, which needs the store. `distance()` and `vector()` need nothing
  but their arguments, so they can come here.
- **The tests:** every expression in the corpus gives 0.x's answer exactly,
  and so do random expressions run against 0.x through `zerox`, as Q3's
  tests do, in a file built only with cgo. Each rule in SQL.md's "Values"
  has a test of its own.
- **Planted bugs,** such as a comparison that converts where SQLite
  doesn't, each with a line in `beta/plants.txt`.
