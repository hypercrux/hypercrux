## The contract

From BETA.md: transactions: the undo list; begin, commit and roll back; the
copy's lock taken at the first change; the error for a call through the
database inside `Update`. Done when random transactions with random
rollbacks match the model under the race detector.

## What's there already

- **The design,** in BETA.md under "Transactions" and "Other processes":
  until its first change an `Update` holds up no reader in its process;
  from the first change to the commit, readers there wait; a call through
  the database inside `Update` that would have to wait for it returns an
  error at once, found by the goroutine's ID from `runtime.Stack`.
- **The store** (S1), in `beta/internal/store`: its write side, `Put`,
  `Delete` and `Drop`, appends the changes each write amounts to, checks
  everything before changing anything, and replaces a record's field slice
  instead of changing it. S1.md's notes under S2 list how to undo each kind
  of change.
- **The error** (P3): `errs.ErrInsideUpdate`.

## To settle, and write down in this file

- **The undo list:** what each entry holds, and how a rollback walks it.
- **Begin, commit and roll back** on the store, and what a commit hands on:
  the change list, for S3 to emit and the log to write.
- **The copy's lock:** a read-write lock, taken for writing at a
  transaction's first change and released at the end, so readers before the
  first change go ahead.
- **The goroutine check** for `ErrInsideUpdate`, and where the public
  package calls it.
- **A failed write inside a transaction:** P5.md's note says a failed
  statement undoes its own changes only, and the transaction carries on.
- **The tests:** random transactions with random rollbacks against a model,
  under the race detector, with readers running alongside.
