# S1: Records, fields and rules

Status: next, in one round with P4 and F1. Planned at 3 hours. It needs P3,
which is done.

## The contract

From BETA.md: records, fields and rules: the hash table, field lists, each
table's field order, and 0.x's rules for keys, fields, link types and
vectors. Done when a random model test and 0.x's rule cases pass.

## What's there already

- **The design,** in BETA.md under "Records", "In memory" and "Keys, fields
  and deletes": a hash table from key to record, each record's fields as a
  short list of field numbers and values, and each table's fields in a fixed
  order.
- **The interfaces** (P3), in `beta/internal/store`: `Reader`, `Record` (the
  fields that hold a value, by their place in the table's list) and `Table`.
  `value.FromGo` is a stub for S1 to write: 0.x's conversions from Go
  values, which P3.md lists.
- **The rules a put keeps,** in FORMAT.md under "Changes": names matched
  regardless of case with the first spelling kept, new fields joining in
  byte order of name, even with a null value, the vector field and its size,
  and at most 65,535 fields a table.
- **0.x's rules,** in `records.go` (`TableOf`, `checkTable`, `checkField`,
  `encodeField`), `links.go` (`checkLinkType`) and `vectors.go`; and the
  conformance cases that pin them, which A1.md lists for S1:
  KeyAndFieldRules, PutAndGetRoundTrip, MoreFieldTypes,
  RulesForLongKeysAndLinkTypes and TableNamesLikeHyperCruxsOwn.

## To settle, and write down in this file

- **The layout:** the hash table, a record's field list, a table's field
  order and its case-folded index, and room for V1's vector slot and S5's
  links.
- **The write side** that S2 wraps in transactions: what a put, a delete
  and a drop look like on the store, taking a put's `[]format.Field` from
  its change, and returning the changes S3 will emit. Undo lists are S2's,
  links S5's, key order S4's and vector arrays V1's; S1 leaves room for
  them.
- **The rules,** as checks the store and the public package share: keys,
  table names, field names, link types and vectors, with 0.x's errors and
  their kinds. P2 and P5 found two that are easy to miss: text has to be
  valid UTF-8, and a link type can't start with a zero byte.
- **The limit on fields:** 65,535, the format's, or SQLite's 2,000 columns
  as 0.x has them.
- **The tests:** a random model test, a plain map against the store, and
  0.x's rule cases run against the store's checks.
