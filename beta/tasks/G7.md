## The contract

From BETA.md: `check`: the in-memory copy's consistency, a damaged batch
named, sizes reported. Done when planted damage in memory and in files is
reported.

## What's there already

- **The promise,** in the comment on `Check` in `beta/hypercrux/check.go`:
  every key starts with its table's name, every link joins two records that
  exist and is listed at both ends, and every vector has its table's size
  and holds finite values that aren't all zero. Check names a damaged batch
  in the file, and reads a single point in the log. For now `count` stands
  in for it, counting from the snapshot, and finds no problems (G1.md's
  note).
- **The store's checks, as tests:** `checkLinks` and `checkVectors` in
  `beta/internal/store/model_test.go`, a start on the store's own check
  (S5.md's and V1.md's notes).
- **Damage** (F1 and F4): a `*errs.Damage` names the batch and an offset
  from its start. The damaged fixtures in
  `beta/internal/logfile/testdata/damaged` have each file's batch and
  offset in `damage.txt`, which a test in `beta/hypercrux` reaches as
  `../internal/logfile/testdata/damaged` (F4.md's note).
- **A failed reload** (F9): every read gives its error until one works
  (`DB.unread`), which Check can report as it stands. `(*Log) Path()` gives
  the real path for a report (F7).
- **Export and Import** (G6): Export's comment says that once Check checks,
  Export refuses a database Check finds problems in, as 0.x's does and
  EXPORT.md says. `importAll` has a comment where a check would go.
- **Sizes:** BETA.md's row on memory under "Risks" says `check` reports
  sizes. `TestTheAPIMatches0x` compares `Report`'s fields with 0.x's
  (P4.md's note), and 0.x's `Report` has the four counts and `Problems`.

## To settle, and write down in this file

- **The store's check:** the copy's consistency, from the records, the
  keys in byte order, the link lists both ways and the vector arrays, as a
  read of the store, with its write path unchanged.
- **A damaged batch named:** what Check gives for a file with damage, for a
  batch the log refused at a follow, and after a failed reload.
- **Sizes:** the file's size and the copy's, and how `Report` gives them
  beside 0.x's fields.
- **Export and Import:** whether Export refuses a database Check finds
  problems in, and whether Import checks the database first, as 0.x does.
- **The tests:** damage planted in memory through a hook in the store's
  tests, and in files, the damaged fixtures among them, each reported: the
  closing test. And Check through the conformance suite on both engines,
  counting the same.
- **Planted bugs,** such as a check that skips a link's mirror, or a vector
  of zeros let through, each with a line in `beta/plants.txt`.
