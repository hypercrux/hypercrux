From BETA.md: benchmarks mirroring 0.1's, with 0.1 run alongside. Done when

## What's there already

- **0.1's benchmarks,** in `bench_test.go` in the repository's root: the
  searches, the walks, the puts, `Get` and `Link`, with the data each
  builds. `scripts/record-tests.sh` records them in `test/results/bench.txt`,
  three runs each, and the README's figures come from there.
- **The targets,** in BETA.md under "Targets": each operation with 0.1's
  figure, the Beta's target and its basis. Cloud machines vary from one run
  to the next, so the two engines are compared from the same run.
- **Who uses the numbers:** G2 times `Get` and `Walk` against their targets,
  F7 checks that a committed put is no slower than 0.1's in the same run,
  I1 times opening 100,000 records, and R4 records them all beside 0.1's.
- **The Beta's public package** (P4 and G1), in `beta/hypercrux`, with 0.x's
  API. `Open`, `Update`, `Put`, `Get` and `Delete` work through the file;
  `Link`, `Walk` and `Nearest` are stubs that name G2, and compacting is
  G5's.

## To settle, and write down in this file

  through its public package, so one run gives both.
- **What the Beta can't run yet,** skipped by name with the task that makes

  that writes it, run the way `record-tests.sh` runs 0.1's.
- **The recorded run:** timings need the machine to itself, and two other
  agents share it this round. Check every benchmark with a short run, and
  leave the recorded run to the coordinator, who makes it once the round is
  merged and the machine is quiet. Say how long it takes.
