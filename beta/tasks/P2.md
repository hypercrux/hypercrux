# P2: File format

Status: done, 7 October 2026.

## The contract

From BETA.md: the file format, byte by byte, with golden fixtures for the
header, each change, the batch, the marker and the compaction header. Done
when the fixtures check out with Go's CRC32C, and a review agent passes the
spec against this plan.

## What was built

- **`beta/FORMAT.md`**, the spec, version 1: the layout, the header, batches,
  markers, the six changes, the six kinds of value, names and limits,
  compaction, reading the log, checking the end of the log (with a table of
  what each torn or damaged end means), writing and creating a database,
  copies, and what isn't in the file. 0.x's `FORMAT.md` and `EXPORT.md`
  are untouched; R3 makes this one the Beta's `FORMAT.md`.
- **`beta/internal/format/testdata`**, 12 fixtures of annotated hex, a
  comment on every field:
  - `header-new.hex` and `header-compacted.hex`;
  - a batch for each change: `batch-create-table.hex`, `batch-put.hex`
    (every kind of value, with -0, subnormals, the i64 extremes, empty text
    and bytes, text beyond ASCII and a vector), `batch-delete.hex`,
    `batch-link.hex`, `batch-unlink.hex`, `batch-drop.hex`;
  - `batch-several.hex` and its `marker.hex`;
  - `file-new.hex`, a small database in three batches, and
    `file-compacted.hex`, the same database compacted into two batches with
    one commit after them. Between them they cover an empty table that keeps
    its vector size, a field no record holds, a null clearing a field, a
    record with no fields, a table created and dropped, and links whose
    order by key differs from the order of their tables.
  - A `README.md` lists them and says how to change one.
- **`beta/internal/format/fixtures_test.go`** checks the fixtures against
  the spec without any codec: every checksum against Go's `hash/crc32` (and
  CRC32C's check value for "123456789"), the framing, every change and value
  against the syntax and name rules, the state rules on the two databases,
  that the compacted one holds the same state as the new one in the order a
  compacted part takes, and that changing any byte of either database, or
  zeros where a batch should be, fails the checks. A wrong checksum is
  reported with the right one, so a fixture can be edited by hand.
- **`beta/internal/format/doc.go`**, so the package exists for F1's codec.
- **BETA.md:** Recovery now says opening looks past the end of the log for
  a marker, which outlasts damage to its batch; the plan points at
  `beta/FORMAT.md`; the backup rule notes that a copy can catch the end of
  the log while it's cut and written again; and a new decision records the
  format.

## The result

- **The fixtures check out with Go's CRC32C.** Their checksums were worked
  out by a bitwise CRC32C written in Python, apart from Go's, so the test
  checks one implementation against the other. The review agent checked
  them a third way, with its own decoder and replay.
- **A review agent passed the spec against BETA.md,** after three rounds.
  Its first pass found the byte layout sound and the crash and damage rules
  holed. The findings, all fixed:
  - Changes that were malformed made a batch "not count", which got it cut.
    Now a batch counts by BETA.md's five checks alone, and bad changes in a
    batch that counts are damage.
  - Damage to the last batch's first bytes got it cut, since the look past
    the end searched for batches. Now it searches for markers, which survive
    damage to their batch, and the marker's check value includes the
    database ID and the generation, so a stored copy of another database, or
    of an older generation, can't pass.
  - Opening didn't look past the end of the log. Now it does, and a reader
    that keeps the database open checks too when the writer is gone.
  - Nothing said how a file comes into being. Now a creator writes a header
    under a `.new-` name, holds `flock` on it, renames it with
    `RENAME_NOREPLACE`, and lets go only after the directory sync.
  - A compacted file could lose its compacted part to a cut. Now a log that
    ends inside it is damage, and no cut reaches into it.
  - The format version now rises with every change, even before the
    release, since an older build reading a newer file could otherwise cut
    it.
  - Smaller points: the limits on batch sizes, the follower reading a
    batch's head and marker first, copies, the order of the check's steps
    and its table, 0.x's rules that text is valid UTF-8 and a link type
    doesn't start with a zero byte (both checked against 0.x), and the
    change order for an untyped unlink.
- `go test -short ./...` and `go vet ./...` pass, and `scripts/check-beta.sh`
  passes.

## Decisions settled

- **Byte order and widths:** little-endian, fixed widths everywhere, so the
  encoding is canonical and encode(decode(b)) == b for valid input. No
  varints, and no alignment: the look past the end steps one byte at a time,
  which only happens on damage.
- **Magic numbers:** `HCRX` CR LF Ctrl-Z LF for the file, as PNG does it;
  `HCRB` for a batch; `HCRM` for a marker.
- **The header,** 68 bytes, with a checksum of its own, which BETA.md didn't
  ask for: a damaged generation would otherwise make every batch fail and
  the whole log look torn.
- **The batch length** is a u64 counting the whole batch, with no limit but
  the file. 0.x's import is one transaction, and a u32 would have capped a
  batch at 4 GB.
- **Kinds as ASCII letters:** changes `T P D L U X`, values `n i r t b v`,
  so a hex dump reads.
- **Field names in every put,** written as the table spells them, in byte
  order, which is the order 0.x adds new fields in. No change adds a field:
  a put's new names join the table.
- **Create changes:** an ordinary commit writes one with no fields and size
  0 before the first put into a table; compaction and any writer that knows
  a table's whole shape write it whole.
- **Sequence numbers** start at 1 in every file. The compacted part's
  batches carry markers like any others, so readers keep one rule.
- **Strictness:** a change that would do nothing is never written, apart
  from puts, so a link added twice, a delete of a missing record and the
  like are damage in a file.

## Notes for later tasks

- **P3, the interfaces:** the value type has the six kinds above, with reals
  and vectors as bits; the change list has the six changes. Error values
  should tell apart damage, a file that isn't a Beta database, a 0.x
  database, and a newer format version.
- **F1, the codec:** match the fixtures byte for byte. The test's reader is
  a starting point, and the fixtures stay the judge: change them only with
  FORMAT.md. Random round trips can check encode(decode(b)) == b.
- **F2, the log and the lock:** the creation procedure under Writing.
  Go's `syscall` package has `SYS_RENAMEAT2` on arm64 (276) but not on
  amd64 (316), and `golang.org/x/sys` can't be fetched here, since the
  module proxy is blocked, so define the number per architecture. Remove
  leftover `.new-` files only when they can be locked. An empty file at the
  path becomes a database by rename under its lock.
- **F3 and F4, recovery and damage:** the steps and the table under
  "Checking the end of the log" are the tests to write. Damage is confirmed
  by a read under the write lock.
- **F5:** a failure while recovery rewrites a batch is handled like a
  failed commit.
- **F6, following:** read a batch's 28-byte head, then look for its marker,
  before reading the batch. When stopped with bytes past its point, try the
  lock without waiting.
- **F8, compaction:** the order under Compaction; batches of about 1 MiB
  keep memory flat; the header can be written last; the markers need no
  sync of their own.
- **G6, import:** write create changes with whole field lists and vector
  sizes. To make an import atomic without one giant batch, it can build a
  whole new database (generation 1) under a `.new-` name and rename it into
  place, as creation does. An export with a vector size but no `vec` field
  breaks the create change's rule: refuse it, or drop the size.
- **S1, the rules:** refuse a put that would take a table past 65,535
  fields, or adopt SQLite's 2,000 columns as 0.x has them. Text is valid
  UTF-8, and a link type can't start with a zero byte.
- **Q6:** SQL writes over many rows go in key order, so the bytes don't
  depend on map order.
- **T3:** a copy taken while the end of the log is cut and written again
  can read as damage; a copy taken any other time opens.
- **R3:** bring compaction's steps and the file rules from BETA.md into
  the final `FORMAT.md`, so a writer needs nothing else.
