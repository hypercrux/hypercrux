# A2: Export and import for 0.x

Status: next. Planned at 4 hours.

## The contract

From BETA.md: JSON lines with each table's vector size and field order,
links, and numbers that read back to the same bits. Done when random files
with awkward values (subnormals, -0, extremes, bytes, Unicode) go through
export, import and export byte for byte.

## Where it goes

Into 0.x itself, at the repository root and in `cmd/hypercrux`, outside
`beta/`. It ships in a 0.x release of its own once it's done, as decided in
BETA.md. That release is 0.2.0, with `Version` raised and the README, the
command's help and the site's reference page updated. The Beta's G6 must read
and write exactly this format, so the format gets written down in the
repository, either in FORMAT.md or a short page of its own.

## To settle, and write down in this file

- **The API:** probably `db.Export(w io.Writer)` and `db.Import(r io.Reader)`
  in Go, plus `hypercrux export FILE` and `hypercrux import FILE` reading and
  writing standard input and output.
- **The lines:** a header line naming the format and its version, then a
  line per table with its name, vector size and fields in order, then the
  records, then the links. Field order is the table's column order in 0.x.
- **Types:**
  - Integers and reals must stay apart: a real 1.0 comes back as a real. Reals
    are written with a decimal point or an exponent, using the shortest form
    that reads back to the same float64, and -0 stays -0.
  - Vector values are written in float32's shortest form.
  - Bytes need a marker that text can't be confused with, for example an
    object holding base64.
- **Values a record can't normally hold:** plain SQL in 0.x can still store
  infinities in a field, or NaN or infinity in a vector. Decide whether
  export refuses them, with a clear error, or writes them in a form import
  understands.
- **Importing into a file that already has records:** refuse, or merge?
  Refusing is simpler and safer.
- **The test:** generate random databases with awkward values, then export,
  import into a new file, and export again, comparing byte for byte. Also
  check that every record, field type, link and vector size comes through,
  and that `Check` passes.
