## The result

- **A1's put, get and delete cases pass after a reopen.**
  - `TestConformance` passes nine of the suite's 25 tests:
    OpenAndReopen, OpenNeedsAFile, PutAndGetRoundTrip,
    PutKeepsFieldsItIsNotGiven, KeyAndFieldRules, MoreFieldTypes,
    GetAndDeleteMissing, NewFieldsShowAtOnce and Vectors. The other 16 are
    skipped by name: six wait for G2, nine for G4 and one for F6.
  - `TestConformanceAfterAReopen` passes the same nine with every read
    through the database made on a fresh open of the file. When a test
    closes a database, every key it named is read once more, then again
    after one last reopen, and the two must agree bit for bit, with
    Check's counts. The run makes 33 reopens and compares 30 keys over 9
    databases.
  - Tried by hand: with commits that skipped the file, the plain run
    still passed, and the reopen run failed seven of the nine.
- **The Beta agrees with 0.x.** `TestTheBetaAgrees0x` runs two seeds of
  1,500 random steps, or 300 with `-short`, on 0.x and on the Beta side by
  side: puts with Go values of every type `Put` takes, awkward and refused
  ones among them, gets, deletes, and Updates of one to five calls that
  commit, return an error or panic. Every answer must match, error messages
  included, and so must every key and Check's counts after each of the
  Beta's reopens. Seed 1 made 600 puts, 188 of them refused, 293 gets,
  157 deletes and 393 Updates, of which 196 committed, and reopened the
  Beta 57 times. Tried by hand: converting the values before the names
  were checked failed it at once.
- **Update rolls back when the commit fails.** On the fault layer's disk,
  the batch's write, its sync and its marker's write fail in turn, six
  seeds each, in an Update that puts, adds a field and a table, and
  deletes. Update gives the disk's error, and the copy reads as it did
  before. A reopen reads the state before, or the whole commit when the
  batch was written whole. No reopen read part of a commit. An Update
  whose function fails, panics, changes nothing or makes only writes that
  fail writes nothing to the file.
- **A reopen reads back what was committed:** -0, subnormals and the
  extremes, text with a zero byte and every length of UTF-8, empty bytes,
  a vector of 65,536 values, a table's spelling of a field and its vector
  size, deletes, a rollback, and 300 commits checked against a model.
- **Two handles on one file:** each Update catches up with the other's
  commits before its function runs. Six goroutines on two handles add one
  to a counter, each reading it first inside its Update, and no add is
  lost. While one handle's Update runs, the other's waits, and gives up
  with `ErrLockTimeout` after its wait.
- **The rules agree.** `TestTheCodecRefusesWhatTheRulesRefuse` makes 20,000
  rounds, or 4,000 with `-short`, of table names, keys, field names, pairs
  of field names, link types, vectors, reals, text and values in the
  vector field, near every edge. The codec refuses exactly what `rules`
  refuses, and each rule both takes and refuses at least 416 of them.
  Tried by hand: a codec that took the field name `oid` failed it, and
  `TestTheRulesEdges`, which pins 31 edges one case each.
- **The planted bugs are caught,** each by the test written for it:
  `append-error-dropped` by the rollback test, `reset-kept` by the moved
  file, `load-after-open` by the batch that breaks the rules, and
  `vector-shared` by the test of the public `Vector`.
- `go vet ./...`, `go test -short ./...`, `go test -race` on `hypercrux`,
  `betax` and `format`, and `sh scripts/check-beta.sh` pass. The public
  package's tests take 4.3 seconds, 1.1 with `-short` and 4.4 with
  `-race -short`. The codec's new test takes 0.8 seconds, and 3.4 with
  `-race`.

## Decisions settled

**The glue.** `target` is the `logfile.Target`:

| Call | While `logfile.Open` reads the file | After that |
|---|---|---|
| `Apply(seq, changes)` | `LoadBatch`, straight into a copy nobody can reach yet | `ApplyBatch`, a transaction of its own, so readers see all of the batch or none |
| `Reset()` | puts `store.New()` in place | the same |

- `DB` holds the copy as an `atomic.Pointer[store.Store]`, since `Reset`
  replaces it from inside `Lock` while readers load it. Each call loads it
  once, and an `Update` loads it again after `Lock`, so its transaction
  begins on the copy that holds the file at the path. The pointer is nil
  once the database is closed, and in a `DB` nothing opened.
- After a `Reset`, readers in this process can see the new copy fill batch
  by batch, and stay part-filled if the new file can't be read. F9 makes
  them wait.
- A batch that breaks the rules for the state is damage: `Apply` returns
  the store's `*errs.Damage` as it is.

**`Update`,** in this order: the copy's `Outside`, the log's `Lock`,
`Begin`, the function, `Commit` with the log's `Append` as its write, and
`Unlock`, deferred so it runs last and on a panic too. `Commit` calls
`Append` only when there are changes, and its undo list puts the copy back
when `Append` fails. An error from `Unlock` is returned only when there's
no other.

**Calls through the database:**

- `Put` and `Delete` are each an `Update` of their own, so a write inside
  an `Update` fails at once with `ErrInsideUpdate`, and so do `Close` and
  a nested `Update`.
- `Get` and `Check` read inside the copy's `Read` and copy out what they
  return. Inside an `Update` a read goes ahead until the first change, and
  then fails at once.
- `Close` checks `Outside` first, since the log's `Close` waits for the
  write lock's mutex. Then the log's `Close` waits for an `Update` under
  way, and the copy goes. Closing again returns nil, as 0.x's does through
  database/sql, and a `DB` nothing opened counts as closed.
- A `Tx` once its `Update` has returned, and a `Tx` nothing made, give
  `ErrClosed` before any check of their arguments.

**`Put`, `Get` and `Delete` keep 0.x's order of errors.** `Put` checks the
key with `rules.TableOf`, then each name with `rules.Field`, then the case
clash, then converts each value with `value.FromGo` in byte order of name,
then calls the store's `Put`, which checks the number of fields and the
vector's size. 0.x checks the names in its map's order, which is random, so
where two names break the rules it can report either; the Beta reports the
first in byte order. `Get` gives each field under its table's spelling, by
`Value.Go`, the vector as a `Vector` of its own, and an empty map for a
record with no fields, as 0.x does.

**`Check` counts until G7.** Four of the suite's put and get cases call
`Check` (P4.md), so it counts from the copy's snapshot: a `CreateTable` is
a table, a `Put` a record, a `Put` with a vector among its fields a vector,
and a `Link` a link, which S5 makes count without a change here. It finds
no problems.

**One set of rules for the codec: a test.** `format/rules.go` keeps its own
code, and `rules_test.go` holds it to `beta/internal/rules` in both
directions. The codec is FORMAT.md's, and a change to what it takes is a
change to what a file may hold, which FORMAT.md and its version have to
follow. Pointed at `rules`, the codec would change with any change to the
API's rules, and the test makes that a decision instead. The codec also
checks a vector's bits where they lie in the batch, which `rules.Vector`
can't do without a copy.

**The suite on the Beta.** `Skip` names each test that waits, with the last
task it needs on the board and the others after it. The run with a reopen
before every read skips the same, and two more for good: GoroutinesShareADB,
whose goroutines share one database, and KilledWritersNeverLeaveAMess, which
opens the file afresh after every kill already.

**The planted bugs:** `hypercrux/append-error-dropped`, an `Update` that
takes no notice when `Append` fails; `hypercrux/reset-kept`, a `Reset` that
keeps the old copy; `hypercrux/load-after-open`, batches after `Open` that
go in without a transaction, so a bad one goes in by halves; and
`hypercrux/vector-shared`, a `Get` that hands out the copy's own vector.

## Notes for later tasks

- **F3:** the log's `readOn` still wraps the store's damage in damage of
  its own, so the message names the batch twice: "...: batch 2 at offset
  156: changes that break the rules for the state they apply to: hypercrux:
  the file is damaged: batch 2 at offset 0: change 2: ...". F3's brief
  takes the store's with `errors.As`. `TestABatchThatBreaksTheRulesIsDamage`
  checks `errors.Is`, the `Batch` that `errors.As` finds, and "change 2" in
  the message, so it passes either way. `TestUpdateRollsBackWhenTheCommitFails`
  takes a reopen that holds the whole commit after a failed sync or marker
  write, which F3's check makes the usual case.
- **F5:** after a failed `Append`, F2's unchecked tail stops later commits
  through the same handle. No G1 test makes one, so F5 can add a later
  `Update` to `TestUpdateRollsBackWhenTheCommitFails`.
- **F6:** a `DB` sees another handle's commits only once an `Update` of its
  own has caught up. `TestTwoHandlesOnOneFile` catches both handles up with
  an empty `Update` before it compares them, and F6 can drop those two
  lines. ProcessesShareAFile waits for F6 in `betax`.
- **F7:** `Open` hands the path to `logfile.Open` as given, so a relative
  path stays relative, and the real path is F7's to settle there.
- **F9:** `target.Reset` and `target.Apply` in `glue.go` are where a reload
  holds readers off and drops the old copy first.
- **G2:** take G2's lines out of `later` in `betax.go` and out of
  `TestTheStubsSayWhatsMissing`. The reopen run then covers `Scan`, links
  and walks through the file too. `Check`'s link count comes from the
  snapshot's `Link` changes once S5 emits them.
- **G4, A3 and P5:** 0.x keeps the new columns of a put that fails inside a
  committed `Update`, since it adds them before it checks the vector's
  size; in the Beta a write that fails changes nothing. So `SELECT *` can
  show a column in 0.x that the Beta's table hasn't got. SQL.md doesn't list
  it yet.
- **G7:** `count` in `check.go` stands in for the real check, which can keep
  its counts.
- **I1:** `OpenWith` in `export_test.go` opens the public package on the
  fault layer's disk.
- **The coordinator:** `beta/README.md`'s line for `hypercrux/` can read:
  "the Beta's Go package, beside 0.x's until the release. It has 0.x's API.
  `Open`, `Close`, `Update`, `Get`, `Put`, `Delete` and `TableOf` work
