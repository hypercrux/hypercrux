# S4: Key order and Scan

Status: next, in one round with G1 and F3. Planned at 3 hours. It needs S1,
which is done.

## The contract

From BETA.md: key order and `Scan`: each table's keys in byte order as they
come and go; `Scan` by prefix, after and limit. Done when the model test and
0.x's `Scan` cases pass.

## What's there already

- **The design,** in BETA.md under "In memory" and "Keys, fields and
  deletes": each table's keys kept in byte order as they come and go, and
  `Scan` reading them in that order, as SQL will, so a query with `LIMIT`
  and no `ORDER BY` gives the same rows in every process.
- **The store** (S1 to S3), in `beta/internal/store`. Keys come and go in
  `put` and `remove` in `write.go`, as S1.md's note under S4 says, and
  `drop` can then look at its table's keys alone. Every change there has an
  undo entry (S2), and the snapshot sorts each table's keys itself for now,
  in `byKey` (S3).
- **The read API** (P3): `Reader.Scan(prefix, after)` returns a `Cursor`
  and takes no limit, since the caller stops pulling; the public package
  applies 0.x's limit and its check that the limit isn't negative.
- **0.x's `Scan`** in `records.go`: the prefix starts with a table's name
  and a colon, records come after `after` in key order, a limit of 0 means
  all of them, and vectors are left out.

## To settle, and write down in this file

- **The structure** that keeps each table's keys in order: inserts and
  deletes cheap with 100,000 or more keys, since opening has to load them
  in about 250 ms with everything else. A sorted slice moves too much for
  that; a B-tree, or keys in order with a little kept aside, are the kind
  of thing to weigh.
- **Undo:** an entry for each change to the key order, so S2's rollbacks
  keep working.
- **`Scan`** on the store and through a transaction, which sees its own
  changes, with 0.x's errors for a bad prefix.
- **What changes because of it:** `drop` visiting its own table's keys
  alone, and the snapshot walking each table's keys in order, so `byKey`
  goes.
- **The tests:** the model test extended with scans, and 0.x's `Scan`
  cases, run against the store and against 0.x side by side as S1 did.
