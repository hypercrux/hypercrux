# P5: SQL subset spec

Status: under way, in one round with P3. Planned at 2 hours. It needs A1 and
A4, which are done.

## The contract

From BETA.md: the SQL subset spec: the grammar, the list of functions, value
rules, and the named 0.x tests the Beta must pass, settling small 0.x
behaviours such as field names that match regardless of case, `SELECT *`
order, comparisons on untyped fields and the scalar `walk()` form. Done when
every corpus statement is marked in or out, and every named test exists.

## What's there already

- **The subset,** in BETA.md under "Queries and SQL": `SELECT` from one table
  with `WHERE`, `ORDER BY`, `LIMIT`, `OFFSET` and aggregates over the whole
  result; `walk(...)` as a table, joined on the key or inside `IN` and
  `NOT IN`, with 0.x's `json_each(walk(...))` forms accepted unchanged; the
  subquery that reads one field of one record by its key; `distance` and
  `vector`, with rows without a vector sorting first; `IN`, `BETWEEN`,
  `LIKE`, `IS NULL` and the text and number functions on a list this task
  fixes; `date` and `datetime` on `'now'` with days, months and years; and
  `INSERT`, `UPDATE` and `DELETE` on one table. "Left for later" lists what
  stays out.
- **The corpus** (A4), in `beta/sqlcorpus`: 289 statements in
  `testdata/statements.jsonl`, each with a first guess at `in`, 3,000
  expressions, and 622 date cases. `cases.go` builds them, and
  `HYPERCRUX_CORPUS_RECORD=1 go test -run TestRecord ./beta/sqlcorpus`
  records 0.x's answers again.
- **0.x's SQL functions** are in `sqlfuncs.go`: `distance`, `vector` and
  `walk`.
- **The test suites** (A1): `beta/conformance` runs 0.x's tests that don't
  depend on SQLite against an `Engine`, and `beta/conformance/cmdtest` runs
  the command's tests against a binary.

## To settle, and write down

- **Where the spec goes:** `beta/SQL.md`, so nothing clashes with 0.x's
  documents.
- **The grammar** of the subset, precise enough for Q3's parser, and every
  corpus statement marked in or out to match it.
- **The functions:** the list, with what each returns, `CAST` and `nullif`
  among the ones to take or leave.
- **Value rules:** SQLite's, for untyped fields: how values compare across
  types, arithmetic, text and number conversions, NULL, `LIKE` and
  collation, as far as the subset reaches.
- **0.x's small behaviours:** field names that match regardless of case,
  `SELECT *` order, comparisons on untyped fields, the scalar `walk()` form
  in or out, and the columns of walk as a table.
- **Errors:** which kind each SQL error is, "no such table" among them,
  since difftest compares errors by kind.
- **The named tests:** the 0.x tests the Beta must pass, by name, from the
  conformance suite and the command's sections, and a test that checks every
  name exists.
