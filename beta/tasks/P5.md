# P5: SQL subset spec

Status: done, 7 October 2026.

## The contract

From BETA.md: the SQL subset spec: the grammar, the list of functions, value
rules, and the named 0.x tests the Beta must pass, settling small 0.x
behaviours such as field names that match regardless of case, `SELECT *`
order, comparisons on untyped fields and the scalar `walk()` form. Done when
every corpus statement is marked in or out, and every named test exists.

## What was built

- **`beta/SQL.md`**, the spec:
  - the rule behind it: a statement inside the subset gives 0.x's answer,
    down to column names, the bits of reals and the kind of error, and one
    outside it is an error;
  - words and symbols: spaces and comments, the reserved words and the six
    that are keywords only in place, names, literals, `?` and the symbols;
  - the grammar, with SQLite's operator levels and the rules a Pratt parser
    follows to build SQLite's trees, signs before literals included;
  - names and columns: how tables, fields and sources are found, and what
    each result column is called, comments included;
  - queries: FROM with walks and the one join, the order of rows,
    aggregates, ORDER BY's three rules, LIMIT and OFFSET, the one-record
    subquery, walks in IN and `Nearest`'s filter;
  - walks, vectors, dates and writes;
  - values: arguments, results, comparing, conversion before comparing,
    truth, arithmetic, numbers as text and text as numbers, CAST, `||`,
    LIKE, IN, BETWEEN and IS, and what gets worked out;
  - each function with what it gives, and the routine in SQLite's source
    behind it;
  - the kind of every SQL error;
  - 0.x's small behaviours, settled, and where the Beta differs from 0.x;
  - the named tests, as a table of all 25 conformance tests and all 11
    command sections.
- **The corpus** (`beta/sqlcorpus`):
  - Every statement's mark was checked against the spec, and all of A4's
    first guesses stood: 235 in and 54 out.
  - The two notes that left a decision to P5 now give it, and every
    statement marked out says why in its note.
  - `TestTheMarksFollowTheSpec` checks that, and that every expression and
    every case on 'now' is in, and every case on a fixed date out.
  - Recorded again. The diff holds 52 changed notes and nothing else: no
    mark and no answer moved.
- **`TestEveryNamedTestExists`** in `beta/conformance/cmdtest/named_test.go`
  reads the table from SQL.md and holds it to `conformance.Tests()` and the
  command's sections. Every row must name a test that exists, and every test
  must have exactly one row. `TestCommands`' sections moved to a
  package-level variable, unchanged, so the test can see them. Breaking the
  table by dropping a row, misspelling a name and garbling a row made it
  fail on each.
- `beta/README.md` lists SQL.md.

## The result

- Every corpus statement is marked in or out to match the spec, and
  `go test ./beta/sqlcorpus` replays all 3,911 cases clean on 0.x twice.
- Every named test exists: the table names 34 tests the Beta must pass and 2
  it leaves out, and `TestEveryNamedTestExists` passes.
- `sh scripts/check-beta.sh`, `go vet ./...` and `go test -short ./...`
  pass.
- The spec's account of 0.x comes from experiments on 0.x and go-sqlite3
  v1.14.52, whose SQLite is 3.53.4, and from that SQLite's source. Two
  findings shape Q1:
  - SQLite read 60,000 numbers, hard cases included, to the same bits as
    Go's `strconv.ParseFloat`.
  - SQLite's text for reals always read back exactly, and it differed from
    Go's shortest form for about half of random reals, so Q1 needs SQLite's
    own rule.

## Decisions settled

- **The function form of `walk()` is in**, giving JSON text as in 0.x.
  WalkInSQL and UpdateIsAllOrNothing use it, and it costs little once walks
  exist.
- **The walk as a table** has the columns `key` and `depth`.
- **The functions** are the ones the corpus checks: `abs`, `coalesce`,
  `ifnull`, `instr`, `length`, `lower`, `upper`, `max`, `min`, `nullif`,
  `replace`, `round`, `substr`, `trim` and `typeof`, the six aggregates,
  `distance`, `vector`, `walk`, `date` and `datetime`, and CAST. CAST takes
  only INTEGER, REAL, TEXT, BLOB and NUMERIC.
- **Field names** match regardless of ASCII case in `Put` and SQL alike, and
  keep the first `Put`'s spelling. **`SELECT *`** gives `key`, then the
  fields in the order `Put` first used them. **Untyped fields** compare as
  they are, and only a numeric CAST converts them, as SQLite's affinity
  does.
- **Error kinds:** "no such table" and every other error SQLite raises are
  "error". A rule broken by a write is "invalid", and so is an error of
  `distance()`, `vector()` or `walk()` inside a write, as in 0.x. In a SELECT
  those are "error". SQL never gives "not found", and the kind follows the
  statement.
- **Writes** apply `Put`'s checks to every row written, so values `Put`
  refuses can't come in through SQL. A statement is all or nothing, inside
  `Update` too, and works from the data as it was before it began.
- **Where the Beta is stricter than 0.x:** one statement a call, exactly as
  many arguments as `?` marks, double quotes as the only quotes for names,
  no aliases in WHERE, and each field once in an INSERT or UPDATE. SQL.md
  lists these.
- **Order:** rows without ORDER BY come in key order, or the walk's, and
  ORDER BY sorts stably.
- **'now'** is read once for each statement.
- **The named tests:** all 25 conformance tests, and 9 of the 11 command
  sections. SQLTriggers and AdoptAndDrop are left out, as A1 expected.

## Notes for later tasks

- **BETA.md:** "Queries and SQL" lists walk as a table and 0.x's json_each
  forms. It should also name the function form, `walk(...)` giving JSON
  text, which this spec keeps. Its line on "the text and number functions on
  a list fixed in task P5" can point to `beta/SQL.md`.
- **P3 and P4:** an SQL value can be text that isn't UTF-8 or an infinite
  real, though neither can be stored, and NaN never appears. A vector reads
  as bytes in SQL. P4's `Open` keeps 0.x's rules, which OpenNeedsAFile
  tests.
- **S1:** a `Put` that names a new field with a nil value still adds the
  field. The command's SQL section depends on it.
- **S2 and Q6:** a failed statement inside `Update` undoes its own changes
  only, and the transaction carries on.
- **Q1:** 627 of the 3,000 expressions use CAST and 141 use `nullif()`. The
  hard parts are SQLite's text for reals (`sqlite3FpDecode`), CAST's
  affinity in comparisons, `min()` and `max()` on ties, and the signs in
  front of literals. SQL.md names the routine behind each rule.
- **Q2:** `dates.jsonl`'s 608 cases on fixed dates check the arithmetic, and
  the SQL takes 'now' only.
- **Q3:** the reserved words and the six in-place keywords, the Pratt rules
  with BETWEEN and the signs, and result column names, which keep comments.
  `--` starts a comment, so the corpus's `--1` is "incomplete input". Every
  statement marked out says why, which can feed its error message.
- **Q4:** `sum()`, `total()` and `avg()` use Kahan-Babuska-Neumaier summation
  in row order. Sorts are stable.
- **Q5:** a nearest search has to raise `distance()`'s errors exactly when a
  row that passes WHERE has a vector, and give distance 1 for a query of
  zeros given as bytes, which `Nearest` itself refuses. A walk from a key
  that isn't a record reaches nothing, without an error.
- **G3:** arguments bind as SQL.md's table says: NaN becomes NULL, and a
  time becomes go-sqlite3's text. Extra arguments are an error,
  `LastInsertId` returns one, and `Query` runs writes and gives no columns.
  Through `SQL()`, 0.x wraps no errors.
- **G4:** difftest's `UPDATE docs SET n = ?` can bind infinity or text that
  isn't UTF-8, which 0.x stores and the Beta refuses, so leave those out of
  its SQL arguments or count them as known differences. Its
  `SELECT count(*), sum(n) FROM people` adds reals in key order on the Beta
  and in insertion order on 0.x, which can change the last bits, or give
  infinity on one side at the extremes.
- **G5:** the command keeps its own check for one statement, with exit code
  2. The Beta's run sets `HYPERCRUX_CMD_SKIP=SQLTriggers,AdoptAndDrop`, and
  the `drop` verb then needs a test of its own.
- **R3:** SQL.md becomes the reference for the Beta's SQL.
