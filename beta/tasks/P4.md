# P4: Package skeleton

Status: done, 7 October 2026.

## The contract

From BETA.md: the package skeleton, 0.x's exported API as stubs. Done when
A1's adapter compiles against it.

## What was built

- **`beta/hypercrux`**, the Beta's public package. It has every exported
  name in 0.x's package apart from `Adopt` (on `DB` and on `Tx`),
  `ApplicationID` and `DriverName`: 65 of 0.x's 69 names, counting each
  method and constant, with 0.x's signatures and its doc comments adapted
  to the Beta. The files follow 0.x's, with `Drop` in `records.go`, since
  the Beta has no schema of its own.
  - **Added:** `Compact()` on `DB`, the Beta's eight error values from
    `errs`, and `Damage`.
  - **Real already,** ported from 0.x line for line: `ParseDirection`, the
    `String` methods of `Direction` and `Link`, `Vector`'s `Bytes`,
    `String` and `Value`, `ParseVector` and `DecodeVector`. `Open` checks
    its path by 0.x's rules before anything else.
  - **Stubs:** the rest. Each returns an error that names the call and the
    task that makes it work.
  - **The constants:** `Version` is "0.0.0-beta" and `FormatVersion` is 1.
    `MaxKeyLen`, `MaxDims`, `MaxK` and `MaxDepth` are 0.x's.
  - `doc.go` says what's real so far and what's a stub.
- **`beta/conformance/betax`**, the adapter for the Beta. Its code is
  zerox's, with the Beta's package imported in place of 0.x's. Only the
  package name, `Name` and two comments differ. Its `TestConformance` is
  skipped until G1, with a message saying so. `TestTheAdapterReachesTheBeta`
  checks what the adapter hands the suite.
- **Tests,** in `beta/hypercrux`:
  - `TestTheAPIMatches0x` reads both packages' source with go/parser and
    holds the Beta's API to 0.x's, as the decisions below describe.
  - `TestEveryErrorIsExported` and `TestTheErrorsAreErrs`: each of errs'
    values is exported as the same value, 0.x's two read as 0.x's do, and
    `errors.As` finds a `*errs.Damage` through `*Damage`.
  - The real helpers against 0.x's own functions, run in one binary on the
    same inputs and compared bit for bit, with the same error texts and
    kinds. `ParseVector` takes 49 awkward cases, 3,000 random arrays and 300
    random strings. `DecodeVector` and `Vector`'s methods take fixed cases
    and 2,000 random blobs and vectors each. NaN payloads, infinities, -0,
    subnormals and numbers past float32's range are among them.
    `ParseDirection` and the two `String` methods take fixed cases.
  - `TestTheStubsSayWhatsMissing` makes all 38 stubbed calls. Each error
    has to read as it should and wrap `errors.ErrUnsupported` and neither
    of 0.x's errors, and the stubs have to do nothing else.
  - `TestOpenRefusesWhat0xRefuses`: 12 names, each refused as 0.x refuses
    it.
  - `TestTheStoreTypesConvert`, `TestTheConstantsAre0xs` and
    `TestFormatVersionIsTheSpecs`.
- `beta/README.md` lists the adapter and says where the package stands.

## The result

- **A1's adapter compiles against the package.** `zerox.go`, copied with
  nothing changed but its package name and its import, built and passed
  `go vet` against `beta/hypercrux` before anything else in it changed.
  Then it got the Beta's `Name` and comments.
- `go vet ./...`, `sh scripts/check-beta.sh`, `go test -race` on the two
  new packages and `go test -short ./...` pass. The package and the adapter
  build with `CGO_ENABLED=0` for amd64 and arm64, and nothing outside their
  tests depends on cgo.
- Tried by hand:
  - `TestTheAPIMatches0x` failed on each of 11 breakages: a method removed,
    a parameter's type changed, an extra name exported, a doc comment
    removed, `Adopt` added, a field's type changed, a value receiver in
    place of a pointer, an error value dropped, `Out` left untyped, a field
    added to `Record` and a field embedded in `DB`.
  - The helper and stub tests failed on each of 14 breakages, among them
    `ParseDirection` ignoring case, `Bytes` writing big-endian, a stub naming
    the wrong task and `Update` running its function.
  - The suite, run on the stubs with the skip taken out, fails 24 tests at
    `Open` with the stub's message and passes OpenNeedsAFile. Nothing
    panics or hangs.

## Decisions settled

**A stub returns an error and does nothing else.** The error comes from
`notYet`, reads `hypercrux: DB.Get is an unsupported operation in the Beta
until task G1`, and wraps `errors.ErrUnsupported`. So `errors.Is` tells a
stub from a failure, and difftest counts it as a plain error, of kind
"error". A test that reaches one fails with a message naming the task,
where a panic would end the whole test binary at the first stub. `Update`
doesn't call its function, and `Open` makes no file.

**`SQL` and `QueryRow`** hand out database/sql values, and nothing outside
database/sql can make a `*sql.Row` that holds an error. Both come from one
handle, `stubSQL`, over a connector whose connections fail with the stub's
error. So `Scan`, `Ping` and `Begin` return that error, and
`SetMaxOpenConns`, which OneConnection calls first, works. The handle is
made on first use, since database/sql starts a goroutine for each handle.

**Which task makes each call work,** as each stub's error says, on `DB` and
`Tx` alike:

| Task | Calls |
|---|---|
| G1 | `Open`, `Close`, `Update`, `Get`, `Put`, `Delete`, `TableOf` |
| G2 | `Scan`, `Drop`, `Link`, `Unlink`, `Neighbours`, `Walk`, `Nearest` without a filter |
| G4 | `Exec`, `Query`, `QueryRow`, calls through `SQL()`, `Nearest` with a filter |
| G5 | `Compact` |
| G6 | `Export`, `Import` |
| G7 | `Check` |

`Path` is real. It gives the path `Open` set, and nothing sets one until G1.

**The doc comments** say what each call does once its task is done, adapted
from 0.x's to BETA.md and the specs, and `doc.go` says once that most of
them are stubs for now. So a task that makes a call work leaves its comment
alone, unless it settles something the comment gets wrong.

**What's real already** holds no state, so it may as well be 0.x's from the
start: the helpers listed above, and `Open`'s rules for a path, which P5's
note asked for and which no internal package owns. They give 0.x's results
bit for bit, with 0.x's error texts, and keep 0.x's quirks:

- `DecodeVector`'s error wraps neither of 0.x's errors;
- `Vector.String` gives "" for a vector holding NaN or infinity;
- `ParseVector` returns the values it read along with an error from the
  vector rules.

`ParseVector` has its own copy of 0.x's vector rules, `checkVector`, until
G1 points it at S1's. `TableOf` stays a stub, since it needs S1's key rules.

**The types are the package's own,** defined here as 0.x defines them.
Aliases of `store`'s would put their docs and methods in an internal
package. This way the API test compares them as written, and the store's
types can change without changing the API. `Link`, `Step` and `Hit` have
`store`'s fields, and `Direction` its numbers, so a plain conversion such as
`Link(l)` turns each of the store's into the package's.
`TestTheStoreTypesConvert` pins that. `Vector` is `[]float32`, as P3 noted.

**The errors** are errs' values under the same names, all ten, as
`var ErrNotFound = errs.ErrNotFound` and so on. `Damage` is an alias,
`type Damage = errs.Damage`, since `errors.As` finds only the same type and
the details of damage have to reach callers. go doc shows its fields under
`errs`.

**`Version` is "0.0.0-beta".** It's a pre-release, so it sorts before every
release and claims no number before R4 picks one. The release workflow reads
`const Version` only from the `hypercrux.go` at the root, and only in the
form X.Y.Z, so nothing in `beta/` can set off a release. Its comment says
so.

**`FormatVersion` is 1,** FORMAT.md's. `TestFormatVersionIsTheSpecs` holds
it to the spec's title and its table of the header.

**The adapter** is `beta/conformance/betax`, package `betax`, beside
`zerox`. Its `Name` is "HyperCrux 0.0.0-beta in Go", beside 0.x's "HyperCrux
0.2.0 on SQLite". `Skip` is empty, since SQL.md names all 25 tests as ones
the Beta must pass. Until G1 the suite can't run at all, since every test
but one opens a database first, so the whole test is skipped with a message
naming G1, in place of 24 entries in `Skip`.

**The API test** keeps the API from drifting either way:

- Every exported name in 0.x's package is in the Beta's, as the same kind
  of name (const, var, type, func or method), apart from the four in
  `leftOut`, which mustn't be there.
- Functions and methods have the same parameter and result types, and
  methods the same receiver, pointer or value. Parameter names don't count,
  since they aren't part of a type.
- A type has the same definition. For a struct that's its exported fields
  in order, and any embedded field, whose methods would join the type's.
  Unexported fields don't count. A constant has the same declared type,
  followed through its const block.
- A name 0.x documents has a comment in the Beta.
- Beyond 0.x's names the Beta exports only those in `added`, each with a
  comment.
- It reads the files a build for this system uses, through `go/build`, and
  prints types from the syntax tree, so `any` and `interface{}` would count
  as different.

It imports neither package, so it needs neither to work. The tests that
check values (the limits, the directions, the errors and the helpers)
import both packages, so the package's tests need 0.x and cgo, as zerox's
and difftest's do.

## Notes for later tasks

- **G1:**
  - Take the skip out of `betax`'s `TestConformance`, and name in `Skip`
    the tests that wait for G2 and G4, each with its task.
  - Four of the suite's put and get cases call `Check`, through `checkOK`:
    OpenAndReopen, PutAndGetRoundTrip, KeyAndFieldRules and
    NewFieldsShowAtOnce. So G1 needs a `Check` that gives the counts,
    though the rest of it is G7's.
  - Point `ParseVector` and `TableOf` at S1's rules, and delete
    `checkVector`.
  - `DB` holds only a path, and `Tx` only its database, for G1 to design.
  - Take G1's lines out of `TestTheStubsSayWhatsMissing`. Each task after
    it does the same with its own.
- **G2:** turn the store's results into the package's with plain
  conversions, element by element: `Link(l)`, `Step(s)`, `Hit(h)`, and
  `store.Direction(d)` going in.
- **G3:** a `*sql.DB` over the Beta's driver for each `DB`, made in `Open`
  and closed by `Close`, in place of `stubSQL`.
- **G5:** the command's version line can give `Version` and
  `FormatVersion`, as 0.x's does.
- **G7:** `TestTheAPIMatches0x` compares `Report`'s fields with 0.x's, so a
  field for sizes needs the test changed to allow it.
- **R4:** set `Version` for the release. The release workflow reads only the
  root's `Version`, so the Beta's release needs the workflow changed too.
- **0.x:** a name added to 0.x's package fails `TestTheAPIMatches0x` until
  the Beta has it, or `leftOut` names it. The test workflow, which 0.x's
  releases wait for, runs it, so a change to 0.x's API comes with a stub
  here.
- **Errors:** a value or type added to `errs` fails
  `TestEveryErrorIsExported` and `TestTheErrorsAreErrs` until it's exported
  here and listed in `added`.
- **The coordinator:** `check-beta.sh` could build `./beta/hypercrux/...`
  with `CGO_ENABLED=0`, to hold BETA.md's promise of a Beta without cgo
  from now on.
