## What's there already

- **The driver** (G3), in `beta/hypercrux/driver.go`: it parses each
  statement, takes its arguments and hands both to an `engine`, which is
  `notYetEngine{}` in `open` until now. G3.md's note says what the engine
  gets and gives, and how the driver copies rows and marks a write.
- **The planner** (Q5): `query.Query(r, s, f)` for a SELECT, and
  `NearestFilter` for `Nearest` with a filter, with 0.x's order of checks in
  Q5.md's note.
- **The writes** (Q6): `query.Exec(tx, s, f)` for an INSERT, UPDATE or
  DELETE, with the row count. Q6.md's note covers a write outside `Update`,
  `Query` of a write, `Exec` of a SELECT and the kinds of errors through
  `SQL()`.
- **Arguments:** `query.Arg` (Q1) and the driver's own conversion (G3), two
  of the same, of which one can go (Q1.md's note).
- **The tests that wait:** nine in betax's `later`, all named for G4, among
  them `KilledWritersNeverLeaveAMess`, which fails at its first `Query`
  (I1.md); the filtered search in beta/bench's `later` (T5.md); and
  `betaLeaves` in `beta/difftest` (G2.md's note).
- **The differential harness** (A3): it runs 0.x against the Beta without
  SQL. Q5.md's note says how its statements can take the crux query in
  0.x's form, and P5.md's which of its SQL arguments the Beta refuses on
  purpose.
- **The corpus** (A4): `sqlcorpus.Replay` can run its cases through an
  engine once SQL works (A4.md's, Q1.md's, Q2.md's and Q6.md's notes).
- **A finding from I1:** when only flock's unlock fails after a commit,
  `Update` returns an error saying the Update failed, though the commit is
  in the file and in the copy.
