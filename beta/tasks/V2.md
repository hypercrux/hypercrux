# V2: Vector blocks

Status: next, in one round with G4, once the owner has settled its scope
(below). Planned at 2 hours, for vector blocks alone. It needs V1, F8 and
S3, which are done, and I1 found the open target missed.

## The contract

From BETA.md: vector blocks, only if the open target is missed: compaction
writes each table's vectors as one block, read on opening without parsing.
Done when a compaction round trip keeps every vector's bits and the open
target is met.

## What's there already

- **The measure** (I1): `BenchmarkOpenFile_100k_384dims` in
  `beta/hypercrux/opening_test.go`, from the log of 20 commits and from that
  log compacted. On a quiet machine I1 timed 769 ms and 638 ms against the
  target of 250 ms, and the coordinator's recorded run after I1 is on the
  board. I1.md's table says where a compacted file's time goes: about 390 ms
  of its 679 is the vectors, and about 250 ms the records, keys, fields and
  hash table, each through the general put path.
- **What vector blocks would save,** by I1's reckoning: about 240 ms, the
  batch copy of the vectors' bytes, the codec's check, the store's decode
  and copy, and most of the reads, so a compacted file would open in about
  440 ms. The rest needs a load of a compacted part that appends keys in
  order, sizes the hash table once and leaves out checks the codec has
  made, and decoding from the read buffer without copying each batch into a
  string (I1.md's note under V2).
- **The compacted part,** in `beta/FORMAT.md`'s "Compaction": ordinary
  batches of creates, puts and links in byte order, which a reader applies
  like any others. The format version is 1, and no byte of it has changed
  since P2.
- **The writer and the reader:** F8's `Compact`, which writes the part from
  the store's `Snapshot`, and Open's read of the log into the store's
  `LoadBatch`. F8.md's note says where a compaction's own time goes, and
  V1.md's and S4.md's where `LoadBatch`'s goes.
- **A finding from I1,** in the log: a commit after a compaction whose
  folder sync failed can be lost at a power cut, once the stuck handle has
  closed. `TestACommitAfterAStuckCompactionLasts` shows it and is skipped.
  I1.md's note has a fix: before its first commit into a file of
  generation 2 or more, a Log syncs the database's folder once.
