# T2: Fault layer for names

Status: next, in one round with S3 and T3. Planned at 2 hours. It needs T1,
which is done.

## The contract

From BETA.md: the fault layer for names: create, rename, remove and
directory sync, each kept or lost at a cut. Done when a rename without a
directory sync can vanish and one with it can't.

## What's there already

- **The fault layer for data** (T1), in `beta/internal/fault`: `Disk`, a
  drive in memory behind `fsys.FS` and `fsys.File`, where names are always
  durable for now. T1.md's note under T2 says where names would be settled:
  `Disk.names` is one map from path to inode, and `cut()` settles data file
  by file, then drops files without a name.
- **What leans on names:** FORMAT.md's "Creating a database" (a `.new-`
  file renamed with `RENAME_NOREPLACE`, then the folder synced) and
  "Compaction" (`NAME.compact` renamed over the database, then the folder
  synced). F8's closing test, and F2's creation, run through this layer.

## To settle, and write down in this file

- **What a cut does** to names changed since their folder's last sync:
  each creation, rename and removal kept or lost, in an order a real file
  system allows. ext4 with its default journal is the model to name, and
  the model shouldn't be kinder than it.
- **What a folder sync promises:** the names in that folder as the calls
  left them. And what syncing a file does for its own name, which on Linux
  is nothing.
- **Owners and permissions:** whether a cut can lose an unsynced change.
- **Keeping T1's API:** T3 is written against it in the same round, so add
  to it and change nothing it already has.
- **The tests:** a rename without a folder sync can vanish and one with it
  can't, and the same for a creation and a removal, with T1's tests still
  passing.
