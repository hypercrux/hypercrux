# F9: Reloading

Status: next, in one round with Q2 and Q4. Planned at 2 hours. It needs F6
and F8, which are done.

## The contract

From BETA.md: reloading: a process that finds a different file at the path
reloads it, and a leftover `NAME.compact` goes after the inode check. Done
when T4 shows every reader seeing every commit in order through
compactions and a backup moved into place.

## What's there already

- **The design,** in BETA.md under "Compaction" and "Other processes": a
  process that finds a different file at the path drops its old copy and
  runs a garbage collection, so memory doesn't double, before it reads the
  new file. Reads in that process wait meanwhile. The same happens when
  someone moves a backup into place.
- **The log** (F6 and F8), in `beta/internal/logfile`: `Follow` returns an
  error that wraps `ErrReplaced` when another file has taken the path, with
  nothing read, and Lock moves to the new file by itself. Removing a
  leftover `NAME.compact` after the inode check is done already, in Lock and
  in the checks Open and Follow make (F8.md).
- **The public package** (G1 to G3), in `beta/hypercrux`: `read` in
  `glue.go` is the one place a read through the database starts, and
  `target.Reset` and `target.Apply` are where a reload holds readers off.
  Its reads don't follow other processes yet, so ProcessesShareAFile waits
  for this task in `betax`.
- **The harness** (T4), in `beta/internal/procs`, with followers (F6). T4.md's
  note under F9 says what a run through compactions and a backup moved into
  place needs: commits worked out from the store's state after a reload,
  and an era for each file.

## To settle, and write down in this file

- **The reload:** a Log call that does what Open's loop does after
  `ErrReplaced`, holding the mutex: the old file closed, the Target reset,
  the garbage collection, the new file read and checked. Then the public
  package's copy taken over, with its readers held off meanwhile.
- **The public package's reads following:** `Follow` before each read
  through the database, before the store's `Read` and outside it (F6.md's
  note), and a reload when it asks for one. ProcessesShareAFile out of
  `later`, and `TestTwoHandlesOnOneFile` without its empty Updates.
- **The tests:** the closing test through T4's harness, followers seeing
  every commit in order through compactions in another process and a
  backup moved into place at random moments, and the public package's two
  handles and two processes on one file. A reload mustn't hold two copies
  in memory at once, and a test shows it.
- **Planted bugs,** such as a reload that keeps the old copy, or reads that
  never follow, each with a line in `beta/plants.txt`.
