# P3: Internal interfaces

Status: done, 7 October 2026.

## The contract

From BETA.md: internal interfaces: the file calls, so a fault layer can sit
under them; the change list; the snapshot compaction reads; the store's read
API; the value type; the operator iterator; error values. Done when it
compiles against stubs.

BETA.md adds that these interfaces change only through a small task that
updates every caller at once.

## What was built

- **`beta/internal/errs`**, the error values: 0.x's `ErrNotFound` and
  `ErrInvalid`, with 0.x's texts, and the Beta's own, `ErrDamaged`,
  `ErrNotDatabase`, `ErrZeroX`, `ErrFormatVersion`, `ErrLockTimeout`,
  `ErrStuck`, `ErrInsideUpdate` and `ErrClosed`. A `*Damage` says where a
  file is damaged (path, offset, batch, reason) and wraps `ErrDamaged`.
- **`beta/internal/value`**, the value type: `Value`, one 32-byte type for
  the six kinds, with its constructors and accessors, `Go` for what 0.x's
  `Get` gives back, `String` in the differential harness's style, and
  `FromGo`, a stub that S1 fills with 0.x's `Put` conversions.
- **`beta/internal/format`**: the change list, `Change` with its `Op`, and
  `Field`, beside P2's fixtures.
- **`beta/internal/fsys`**, the file calls: `File` and `FS`, 9 methods each,
  and `Info`.
- **`beta/internal/store`**, the read API: `Reader`, 7 methods, with
  `Cursor`, `Filter`, `Table`, `Record`, `FieldValue`, `Direction`, `Link`,
  `Step` and `Hit`.
- **`beta/internal/query`**, the operator iterator: `Rows`.
- **`beta/hypercrux/doc.go`**, the place of the Beta's public package.
- **Tests:** a stub of every interface, in each package's tests, and a test
  that calls every method. Besides those:
  - `errs`: every error through `difftest.Kind`, plain and wrapped, and
    `errors.Is` telling each one from every other.
  - `value`: bits kept for -0, subnormals, extremes and a NaN's payload; a
    vector's bits laid out as `conformance.Vector.Bytes` lays out 0.x's
    blob; what `==` means; `Go`; the panics; the size, 32 bytes.
  - `format`: every change in P2's fixtures, as `fixtures_test.go` reads
    them, goes into a `Change` and comes back the same. Every kind of change
    and value is among them, and each vector's bits must equal the file's
    bytes. Tried by hand: losing the sign of -0 fails it.
  - `fsys`: `Info.Same`, and that `syscall` has the calls F2 needs on the
    architecture it runs on.
  - `store`: `Record.Field`, and that `Link` and `Direction` print as 0.x's
    do.
- `beta/README.md` lists the new packages.

## The result

- **It compiles against stubs.** `go vet ./...` and `go test
  ./beta/internal/...` build every interface with a stub that implements
  it, written in another package, as Q4's fake store will be. `go vet`
  passes for linux/arm64 too, and for darwin and windows, where the packages
  are empty.
- `go test -short ./...`, `go test -race -short ./beta/internal/...` and
  `sh scripts/check-beta.sh` pass.
- The packages import each other one way only, as the table below shows, so
  there's no cycle.

- `store` and `logfile` don't import each other. The public package joins
  them: the log hands each batch it reads to a function as a change list,
  and takes compaction's snapshot as an `iter.Seq[format.Change]`.
- `query` imports `store`, and `store` doesn't import `query`: SQL hands a
  search its WHERE clause as a `Filter`.

**The public package** is `beta/hypercrux`, package `hypercrux`, imported as
`github.com/hypercrux/hypercrux/beta/hypercrux`. The package name is the
same as 0.x's, so a program moves across by changing its import path, and
tests import both into one binary under two names. Only `doc.go` is there
for now. The command can follow at `beta/cmd/hypercrux` (G5).

**The value type.**

- One struct of 32 bytes: a kind, 8 bytes for a whole number's or a real's
  bits, and a string for text, bytes or a vector. The zero value is null.
  Nothing in it changes once it's made, so values copy and share freely,
  and `==` is identity: the same kind and the same bits.
- Reals keep their bits. A vector keeps its values' bits as FORMAT.md
  writes them, 4 bytes a value, little-endian. That's 0.x's blob layout too,
  so SQL can hand a vector out as the blob 0.x gives, and read a blob
  argument as a vector, with no conversion. That costs a copy each time a
  vector moves between a `Value` and a `[]float32`. A put and an open make
  that copy anyway, into the table's array.
- Text and bytes are separate kinds even with the same bytes. Text may hold
  bytes that aren't UTF-8, since SQL can make such text; S1 checks text
  that's stored.
- The accessors panic on the wrong kind, as Go's `log/slog` values do.
- The kinds come in FORMAT.md's order, and the Go types take no side on
  SQL: how values compare and convert, affinity included, is P5's to set
  and Q1's to write.
- 0.x's Go values: `FromGo(field, v)` converts what `Put` takes, and its
  comment lists 0.x's conversions. `Go` gives back what `Get` gives.
- The store keeps a record's vector in its table's array (V1): the record
  holds its slot's number, and reads hand the slot out as a `[]float32`
  without copying it. A vector is a `Value` only in change lists and in SQL.

**The change list** is one struct, `format.Change`, holding an `Op` and the
fields of all six changes; each change uses its own and leaves the rest
empty. Building a change list costs nothing per change beyond a put's
fields, and applying one is a switch. A put's fields are
`[]format.Field`, a name and a value each, in byte order of name, spelt as
the table spells them. The format's kind letters stay in the codec.

**The snapshot** is `Reader.Snapshot()`, an `iter.Seq[format.Change]`: the
changes of a compacted part, in FORMAT.md's order, one at a time.
Compaction encodes them with the codec that encodes commits, export reads
the same stream, and S3's test applies it to an empty store. Taken from a
read, it sees one point in the log. A put's field slice is used again for
the next put, so nothing is copied beyond the record it's on.

**The read API** is `store.Reader`: `Table`, `Get`, `Scan`, `Neighbours`,
`Walk`, `Nearest` and `Snapshot`.

- A record is a plain struct: its key, the fields that hold a value as
  pairs of a place in the table's field list and a value, in that order
  (BETA.md's "short list of field numbers and values"), and its vector's
  slot. Reading one allocates nothing, and Q4's fake store can build them.
- `Scan` returns a `Cursor` to pull from, since SQL's operators pull their
  rows, and a push iterator would need `iter.Pull` for every row. It takes
  no limit: the caller stops pulling.
- `Nearest` takes a `Filter`, `func(Record) (bool, error)`, called for each
  record with a vector, perhaps from several goroutines at once, so a later
  search split across cores needs no change here.
- The transaction inside `Update` is a `Reader` too, and sees its own
  changes.
- Each method keeps 0.x's rules and errors, so the store is the one home of
  0.x's rules (S1), for the Go API and SQL alike.
- What a read hands out is good until the read ends, or inside a
  transaction until its next change.

**The operator iterator** is `query.Rows`: `Next() bool`, `Row()
[]value.Value`, `Err() error` and `Close()`, pulled as database/sql's rows
are. A row is good until the next call to `Next`, so operators can use
their buffers again. `Close` returns nothing, since every operator reads
memory. The planner keeps the column names.

**The file calls.**

- `fsys.File` has `ReadAt`, `WriteAt`, `Sync`, `Truncate`, `Stat`, `Chown`,
  `TryLock`, `Unlock` and `Close`. `fsys.FS` has `Open`, `Create`, `Rename`,
  `RenameNoReplace`, `Remove`, `SyncDir`, `Stat`, `RealPath` and `List`.
- An append is a `WriteAt` at the end of the log. Nothing opens a file with
  O_APPEND, so a fault layer sees one kind of write.
- The lock is `TryLock` and `Unlock`. The wait of up to 10 seconds, and the
  mutex in front of flock, are the log's (F2).
- `Create` makes a file with O_EXCL and exactly the permissions given, and
  `Chown` gives it an owner where that's allowed.
- `RenameNoReplace` is renameat2 with RENAME_NOREPLACE, through
  `syscall.Syscall6`. `syscall` has its number on arm64 (276) and not on
  amd64 (316), and exports neither AT_FDCWD (-100) nor RENAME_NOREPLACE
  (1), so F2 defines them. The EINVAL renameat2 gives for a flag the file
  system lacks becomes an error matching `errors.ErrUnsupported`.
- Errors are the system's, wrapped with the path, so `errors.Is` matches
  `fs.ErrExist` and `fs.ErrNotExist`.

**The error values,** with the kind each has in difftest:

| Error | Kind | Means |
|---|---|---|
| `ErrNotFound` | not found | 0.x's |
| `ErrInvalid` | invalid | 0.x's |
| `ErrDamaged`, and a `*Damage` | error | the file is damaged |
| `ErrNotDatabase` | error | the file isn't a HyperCrux database |
| `ErrZeroX` | error | the file is a 0.x database, in SQLite |
| `ErrFormatVersion` | error | a format version this build doesn't read |
| `ErrLockTimeout` | error | the write lock didn't come free in time |
| `ErrStuck` | error | a handle refusing writes after a failed cut |
| `ErrInsideUpdate` | error | a call through the database inside its own `Update` |
| `ErrClosed` | error | a call after `Close`, or on a transaction after its `Update` |

- 0.x gives a plain error, of kind "error", for a damaged file, a file
  that isn't a database, a newer format, a lock it waited 10 seconds for and
  a closed database. So the Beta's errors wrap neither of 0.x's two, and
  their kinds match 0.x's wherever 0.x has an answer.
- `ErrClosed` wasn't on the list. Every handle needs it from P4 on, and
  adding it later would take a task of its own.
- `ErrFormatVersion` covers an older version too, since before the release
  every change to the format raises it.
- The public package exports these same values, so `errors.Is` works
  across the layers.

**The stubs** sit in each package's tests, in packages of their own, as
callers' fakes will. The only stub in the code itself is `value.FromGo`.
When an interface changes, its stub stops compiling, which marks the change
as one for a task that updates every caller.

**In `format`,** the value package is imported as `val`, since
`fixtures_test.go` has a type called `value`.

## Notes for later tasks

- **P4:** fill `beta/hypercrux`. Export the errors as the same values,
  `var ErrNotFound = errs.ErrNotFound` and so on, with the Beta's own if
  they're wanted in the API. `store`'s `Link`, `Direction`, `Step` and `Hit`
  match 0.x's field for field, `String` methods included, so the public
  package can alias them or copy them. `Vector` is based on `[]float32`, so
  `[]float32(q)` hands a query to `Nearest` without a copy. The adapter for
  the conformance suite goes beside `zerox`.
- **F1:** encode and decode `[]format.Change`. A vector's `Raw()` is the
  bytes that follow its count, and `value.VectorBits` makes a vector of the
  bytes read. A decoder can make one string of a whole batch and slice
  text, bytes and vectors out of it, as long as the store copies the text it
  keeps. `TestChangesCarryTheFixtures` can switch to the decoder.
- **F2:** write the real `FS` and `File` over `syscall`, as a type in
  `fsys` (`fsys.OS`, say), with O_CLOEXEC on every open, fdatasync for
  `Sync`, fchmod after `Create` so the umask doesn't change the
  permissions, EINTR tried again, and `ReadAt` keeping io.ReaderAt's
  promise. On an architecture other than amd64 and arm64,
  `RenameNoReplace` can fail with `errors.ErrUnsupported`. The log goes in
  `beta/internal/logfile`.
- **F7:** a refused path should give 0.x's kind where 0.x has one: "error"
  for a directory. 0.x opens a file with two names, so that refusal is the
  Beta's own; `ErrInvalid` fits it, as it does 0.x's refusal of
  `:memory:`.
- **F8:** take the snapshot from a read after the commit that set the
  compaction off, since a transaction's snapshot would include its own
  changes, and encode it in batches of about 1 MiB.
- **S1:** write `value.FromGo`. The public `Vector` is a named type, so it
  reaches `FromGo` as a `[]float32` only by reflection or by the caller
  converting it. A record's `Fields` are sorted by place, with nulls and the
  vector left out. The write side, `Put`, `Delete`, `Link`, `Unlink` and
  `Drop` on a transaction, is S1's and S2's to settle; a put can take the
  `[]format.Field` its change carries.
- **S2:** the transaction implements `store.Reader`.
- **S3:** emit changes by FORMAT.md's rules, which `format.Change`'s comment
  repeats, and write `Snapshot`.
- **S4:** `Scan` returns a `Cursor`, and the public package applies 0.x's
  limit and its check that the limit isn't negative.
- **V1:** `Record.Vec` is the record's slot. `Nearest` calls its `Filter`
  before the dot product.
- **Q4 and Q5:** each operator is a `query.Rows`, and a scan wraps a
  `store.Cursor`. A fake store implements `store.Reader`, as the stub in
  `store`'s tests does. Reading `vec` as a value is `value.Vector(r.Vec)`,
  which copies, so a planner testing `vec IS NOT NULL` can look at `r.Vec`.
- **G3:** a vector goes out to database/sql as its `Raw()` bytes, the blob
  0.x gives.
- **G7:** a `*errs.Damage` names the batch and its offset. The store's own
  check and its counts are G7's to add.
- **T1 and T2:** wrap `fsys.File` and `fsys.FS`, in `beta/internal/fault`.
