# F6: Following other processes

Status: next, in one round with G2 and Q3. Planned at 3 hours. It needs F3
and T4, which are done.

## The contract

From BETA.md: following other processes: `stat`, reading on, applying
marked batches, the check when the writer is gone. Done when T4 shows every
reader seeing every commit in order, with writers killed at random.

## What's there already

- **The rules,** in FORMAT.md under "Reading the log": a reader that keeps
  the database open reads on from where it stopped, each batch's head
  first, then its marker, then the rest, and applies each batch that's
  complete and marked, keeping nothing unmarked for next time. When it
  stops with bytes past its point, it tries the write lock without waiting,
  and if it gets it, the writer is gone, so it checks the end of the log. A
  file shorter than the point it has applied is damage. BETA.md's "Other
  processes" adds the `stat` before each read, which finds a file that's
  grown, or another file at the path.
- **The log** (F2 to F5), in `beta/internal/logfile`: `readOn`, `tryCheck`,
  F4's `confirm` and `errReplaced`, and comments starting with F6 where the
  follower goes.
- **The harness** (T4), in `beta/internal/procs`: the real log runs under
  it with readers that open the file afresh. T4.md's note under F6 sets out
  a follower's workload, and a gap with no writer, so a follower finds the
  writer gone and runs the check itself.
- **How the store takes a batch** (S2 and S3): `ApplyBatch` is a
  transaction of its own, so it waits for an `Update` under way.

## To settle, and write down in this file

- **The follower's API** on the log: the `stat` and the read on in the
  follower's order, and what it reports when the file has shrunk, or
  another file has taken the path, which F9's reload takes up.
- **Its place beside the writer:** the Log's read position belongs to the
  holder of the mutex, and a commit in this process moves it too (S2.md's
  note). A follower can skip reading on while the mutex is held.
- **The writer gone:** the try at the lock without waiting and the check of
  the end of the log, with the cheap test F4.md's note gives before a wait
  for the lock to confirm damage.
- **A stuck handle** (F5): whether it follows other processes' commits.
- **The tests:** the closing test through T4's harness, followers seeing
  every commit in order with writers killed at random, with gaps with no
  writer; and in `logfile`'s own tests, the follower's cases one by one,
  among them a failed commit's batch cut back and written over while it
  reads, which F5.md's note gives the shape of.
- **Planted bugs,** such as a follower that applies a batch before its
  marker, or keeps an unmarked batch, each with a line in
  `beta/plants.txt`.
