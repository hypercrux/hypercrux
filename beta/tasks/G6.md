# G6: Import and export in the Beta

Status: next, in one round with F7 and Q5. Planned at 2 hours. It needs G2
and A2, which are done.

## The contract

From BETA.md: import and export in the Beta: the same JSON lines as A2.
Done when going from 0.x to the Beta and back gives a byte-identical
export.

## What's there already

- **The format,** in `EXPORT.md` at the repository's root, and the package
  that reads and writes it, `internal/export`, which 0.x's `Export` and
  `Import` use (A2).
- **The public package** (G1 to G3), in `beta/hypercrux`: `Export` and
  `Import` are stubs that name G6.
- **The store** (S3 to V1): `Snapshot` gives the whole copy in byte order of
  tables, keys and links, and `Tx.Apply` takes a `CreateTable` with its
  field list and vector size whole (S3.md's note).
- **The log** (F8): `Compact` writes a whole new file from a snapshot and
  switches it in, which P2.md's note suggests an atomic import could use.

## To settle, and write down in this file

- **Export,** from a read of the copy, in A2's order and A2's bytes.
- **Import,** into a database that holds no record tables, as 0.x requires,
  with each table's field order and vector size kept, and every value
  through `Put`'s conversions (A2.md's note). Whether it goes in one
  transaction or as a new file switched in, and what a failure leaves.
- **Errors,** with 0.x's texts where the command's tests look for them:
  "already holds record tables" and "not a valid HyperCrux export".
- **The conformance suite:** `Export` and `Import` on its `DB` interface,
  and a round-trip test that runs on both engines.
- **The tests:** 0.x to the Beta and back, byte for byte, on A2's random
  files with awkward values: the closing test. And the Beta to 0.x and
  back.
- **Planted bugs,** such as fields written in another order, each with a
  line in `beta/plants.txt`.
