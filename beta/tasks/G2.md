## Decisions settled

**The calls,** on `DB` and on `Tx`, each through the store as the notes of
S4, S5 and V1 said:

| Call | Through the database | Through a transaction |
|---|---|---|
| `Scan`, `Neighbours`, `Walk`, `Nearest` | a read inside the copy's `Read` | the copy's transaction, which sees the Update's changes |
| `Link`, `Unlink`, `Drop` | an `Update` of its own | the copy's transaction |

- **A read through the database** goes through `read` in `glue.go`: one
  `Read`, so it sees one point in the log, and everything it gives is
  copied out before the lock goes. Inside an `Update` it goes ahead until
  the first change and then fails at once with `ErrInsideUpdate`, as G1
  settled for `Get`, since `Read` checks for that itself.
- **A write through the database** is an `Update`, so it fails at once
  inside an `Update`, and commits nothing when it changes nothing: a link
  that's there already gives no change, as S5 settled, and an unlink or a
  drop that fails changes nothing.
- **The checks and the errors are the store's,** which are 0.x's, in
  0.x's order. The public package adds only `Scan`'s limit, `ErrInvalid`
  with "limit -1", checked after the prefix as 0.x checks it. A `Tx` once
  its `Update` has returned, and a closed `DB`, give `ErrClosed` before any
  check of the arguments, as G1 settled.

**The results** are the store's, turned into the package's types element
by element, as P4.md's note said: `Link(l)`, `Step(s)` and `Hit(h)`, and
`store.Direction(d)` going in. Each comes in a list of its own, so the
caller can keep it, and nil stays nil:

- `Scan` gives each record a `Fields` of its own, with the fields that
  hold a value under its table's spelling, by `Value.Go`, so bytes are
  copied, and without the vector. A record with no fields gets an empty
  map, as in 0.x, and a scan that finds nothing gives nil.
- `Neighbours` and `Walk` give nil when there are none.
- `Nearest` gives nil for a table with no vector size, and an empty list
  for a search that finds nothing in a table with one, as 0.x does.

**`Nearest` with a filter** stays the stub that names G4, and the stub
comes first, before `ErrClosed`, as every stub does (P4). A `where` of
spaces is no filter, as in 0.x. Without a filter `args` aren't used. 0.x
hands them to database/sql all the same, which refuses one of a type it
can't convert, such as a channel, a struct or a `[]float32`, with a plain
error, where the Beta searches. That's left for G4, whose `Nearest` takes
its arguments through the driver.

**A failed Put's fields: a difference on purpose.** In 0.x a Put adds the
columns for its new fields before it checks the vector's size, and when
that check fails, they stay in the transaction, and in the file if the
Update commits. The Beta's Put changes nothing when it fails, as S1 and G1
settled. So after a Put of `Title` with a vector of the wrong size, a Put
of `title` in the same Update, or after it commits, is spelt `Title` in
0.x and `title` in the Beta, and `Get` and `Scan` show the difference.
SQL.md and beta/README.md list the failed Put's fields and leave this
effect out. `TestAFailedPutLeavesNoField` pins it, and fails if 0.x
changes.

- `TestTheBetaAgrees0x` notes each Put that 0.x refuses for its vector's
  size inside an Update, and while that table lasts in 0.x, compares its
  field names regardless of case and counts how often that's needed: 28
  times in 40,000 steps of seeds 130 to 137, none in the three seeds it
  runs.
- The differential harness compares field names regardless of case
  throughout. It compares only the kinds of errors, so it can't tell which
  Put failed for its vector's size, and a check as fine as the agree
  test's wasn't worth its weight there. The agree test and S1's tests keep
  the spelling exact.

**The suite on the Beta.** ProcessesShareAFile reads through its own
handle what other processes commit, which needs the public package's
reads to follow them. F6 brings following to the log, and F9 joins it to
the public package (F6.md), so its entry in `later` names F9. When a test
closes a database, the reopen run compares each key's links both ways
too, so a link that didn't reach the file shows there.

**The differential harness.** `TestZeroxAgainstTheBeta` leaves out
`betaLeaves`, the kinds "sql" and "where", until G4.
`TestSavedSequences` replays a saved sequence with 0.x against the Beta,
or with 0.x against itself while it holds a step of those kinds.

**The planted bugs:** `hypercrux/scan-limit-first`, `Scan` checking its
limit before its prefix; `hypercrux/scan-vector-kept`, `Scan` giving each
record's vector; `hypercrux/neighbours-unlocked`, `DB.Neighbours` reading
the copy without `Read`; `hypercrux/nearest-nil-for-none`, `Nearest` giving
nil for a search that finds nothing in a table with a vector size; and
`hypercrux/filter-ignored`, `Nearest` searching without its filter.
