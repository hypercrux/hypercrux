# F7: File rules and growth

Status: done, 9 October 2026.

## The contract

From BETA.md: file rules and growth: real paths, hard links refused, the
sync cost of a growing file measured. Done when the rules have tests, and a
committed put is no slower than 0.1 in the same run.

The rules and their tests are below. The check that a committed put is no
slower than 0.1 is the coordinator's recorded run of the benchmarks, after
the merge, under "The recorded run".

## What was built

## Decisions settled

**The real path.** Open makes the path real before anything else, with
`fsys.RealPath`: every symbolic link resolved, `.` and `..` worked out, and
a relative path made absolute from the working folder's real path. A path
that names nothing yet, for a new database, becomes its folder's real path
and its name. The Log works from that path, and from the folder it's in,
from then on: Follow's stat, Lock's look at the path, Reload, the `.new-`
files a creation makes and a writer removes, and `NAME.compact`. So a
compaction through a link replaces the file the link leads to, and the link
stays. `Path()` on the log gives the real path; the public package's `Path`
gives the path as given, as 0.x's does.

**What a relative path becomes.** The absolute path of the file it named
when Open ran. Changing the working folder afterwards changes nothing for
that handle, and a database the same relative path names from the new
folder is another database.

**The refusals, and their errors.** P3.md's rule: 0.x's kind where 0.x
refuses the same file, and `ErrInvalid` where the refusal is the Beta's
own.

| At the path | Refused | The error wraps | Why |
|---|---|---|---|
| A file with two names or more | at Open, at a reload, by a writer once it holds the lock, by a compaction before its rename | `ErrInvalid` | a compaction replaces the file at one path, and the other names would keep the old file |
| A folder, a FIFO, a device, a socket | at Open and at a reload, from a stat, before anything opens it | `ErrNotDatabase`, of the kind "error", as 0.x's is | opening a FIFO for reading waits for a writer, and opening a device can do whatever the device does |
| A symbolic link to nothing | at Open | `ErrInvalid` | a new database's rename into place would replace the link |
| A last element that has become a symbolic link since Open | at a reload, by a compaction and by `adopt` before their renames | `ErrInvalid` | the rename would replace the link, and leave the file it leads to with the old data |

- The log opens files for reading and writing, which Linux lets through
  at once for a FIFO, so it was never going to hang there. But that open
  still lets a writer waiting at the FIFO's other end go, and the first
  Lock made a database of the FIFO, which reads as an empty file, and
  renamed it over the FIFO. As root it would do the same to `/dev/null`.
  So the stat comes first, and the fstat after the open is a backstop for
  a file that took the path in between.
- A folder has two names or more itself, so the kind is checked before the
  number of names, and a folder gets the folder's error.
- A file with no name, removed or replaced since it was opened, is the
  inode check's to deal with, as before, and isn't refused.
- 0.x makes a database where a symbolic link to nothing leads. The Beta
  can't do that without reading the link, which isn't one of P3's file
  calls. Without the refusal, Open took the taken name for another
  creator's database and tried again 100 times.

**Later, at a reload and at a writer's check.** A file that breaks a rule
can take the path while a process has the database open: a FIFO moved over
it, a backup with a second name moved into place, or a symbolic link.

- At a reload, Open's loop, Lock's move to another file and Reload, the new
  file is checked by Open's rules before it's opened, and before the Target
  is reset. A refusal leaves the Log as a reload whose open failed leaves
  it: on the file it had, or on none once Lock has let go of that. The
  Target keeps the copy it had, unread. Every read gives the refusal, since
  Follow reports `ErrReplaced` again and Reload refuses again, and so does
  every write, until a file that keeps the rules is at the path. Then the
  next read or write moves to it.
- At a writer's check, a hard link made to the open file gives it a second
  name without any other file taking the path, so no reload sees it. Lock
  checks the number of names in the fstat it makes for the inode check, at
  no cost, and refuses; a compaction checks again just before its rename,
  in the stat it makes there anyway, in case the link came while the
  transaction ran. Reads go on: they write nothing, and the file is the
  same one.
- A symbolic link that takes the path and leads to the database's own file,
  by another name, is the same file to every stat. Commits go on into it,
  which does no harm. The renames over the path, a compaction's and
  `adopt`'s, check the path's last element just before, which costs one
  RealPath call, or two when a folder on the way has become a link. A
  folder on the way that has become a link does no harm, since a rename
  through it renames within the folder it leads to, so that's let through.
- Lock doesn't resolve the path again on every commit, which would cost a
  committed put a few lstat calls.

**Leftovers and the waiter's look.** `NAME.compact` and the `.new-` files
are opened only once a stat has found a regular file there, so nothing the
log names is opened when it's a FIFO or a device. With nothing there, the
look costs one call, as it did: a stat where it was an open.

**The sync cost of a growing file.** `BenchmarkCommitSync` measures it at
the file, with the log's own calls, since the log itself can only append:
bytes past the end of the log are a torn end to the check, which cuts them
off. Writing zeros ahead of the log, or reserving room, needs the check of
the end of the log to read the file differently, and that's for after the
Beta, as BETA.md says, if the figures call for it. What they mean for the
targets, once the coordinator's run gives them:

- A committed put is one sync of a file that grows by its batch and its
  marker. What `append` costs over `zeros` for a put of 96 bytes is what
  writing zeros ahead would take off every committed put. The recorded run
  before F7 had the Beta 13 per cent under 0.x with that cost in it, and
  SQLite's WAL is written from its start again after each checkpoint, so
  most of 0.x's commits write into room the file has. So the check in the
  contract doesn't need zeros ahead.
- A batched put pays one sync of 1.6 MB for a thousand records, so what
  `append` costs over `zeros` there is a thousandth of the difference a
  put, under a microsecond even on the drive here, against a target of
  5 µs. The batched put's time is in the processor, above.

**The batched put.** F7 changed what was within its reach: the codec's
buffer, the log's buffer, the store's undo list and the codec's check of a
vector. What's left is in the notes for I1. Nothing in the format, its
version or the store's exported API changed.

## Notes for later tasks

- **I1, the batched put:** about 10 µs a put is left against the target of
  5 µs, going by the shares above:
  - The public package takes a third. `value.FromGo` checks the vector by
    `rules.Vector` and copies it into a `Value`'s string, the store decodes
    it back into float32s, works out its dot product, which is the store's
    whole check, and copies it into its slot, and the codec checks it again
    and copies it into the batch. A put that hands the store the
    `[]float32` as it is would drop one copy and two passes over the
    vector. That needs the store's put to take a vector besides
    `[]format.Field`, an API change.
  - The codec's own check of every change takes 7 per cent, most of it the
    vector's: changes the store has checked could go through an encoder
    that trusts them, as F8.md's note asks for compaction. That's a new
    exported function in `format`.
  - Copying a vector into its slot in its table's array costs a tenth,
    which is slow for 1.5 KB, and looks like the cost of touching new
    memory: the slots of a growing table are in blocks just allocated. A
    table's records in a hash map that grows, and its keys in byte order,
    cost about as much again. Those are the store's design, S1's, S4's and
    V1's.
  - The sync is about 1.1 ms for 1.6 MB at F8's rate, a microsecond a put.
  - The garbage collector marks on the other core while the puts run. How
    often it runs is GOGC's to set, and GOMEMLIMIT's, for each program.
- **I1, the many-process suites:** a database opened through a link or by
  a relative path works from its real path in every process, so a backup
  moved into place there is found by all of them.
- **G5, `Compact()` and the compaction after a commit:** Compact can fail
  before its switch by the file rules, with an error that wraps
  `ErrInvalid`, when a hard link has been made to the database, or a
  symbolic link has taken its path, since it was opened. The database
  carries on in its old file, as after any compaction that fails before the
  switch, and `Due` waits until the file has grown by as much again. The
  command's `compact` verb, run against a file with two names, fails at
  Open with `ErrInvalid`.
- **G6, the public package:** `Open`'s comment could end: "A folder, a
  FIFO, a device or a socket at the path is refused with an error that
  wraps ErrNotDatabase, before anything opens it, and a file with more than
  one hard link, or a symbolic link that leads to no file, with one that
  wraps ErrInvalid. A hard link made while the database is open makes every
  write fail with ErrInvalid until it's gone." The time a batched put spends
  in `convert` is in the note for I1.
- **G7, `check`:** `(*Log) Path()` gives the real path, for a report.
- **R1, long runs:** `BenchmarkCommitSync` is the measure to repeat on
  other drives and file systems, ext4 and XFS at least. The log names the
  real path in its errors and damage now, and its tests compare a damage's
  path with the one they opened under `t.TempDir()`, which is real in
  Linux's `/tmp`. With TMPDIR set through a symbolic link, those
  comparisons would fail.
